# Owner direction: the site leads with what the ontology enables

**Who said it:** Thomas Amann, repo owner.
**When:** 2026-10-20, S043, after the agent brought the explorer up to date with Package 4.
**Where:** a Claude Code chat session.
**Relayed by:** the S043 agent, transcribed the same session.
**Status:** recorded in S043; planned in `docs/SITE-REWORK.md` (deleted when done, in git) and
carried out over S043 and S044. See ADR-0145 and `review/rulings/2026-10-20-chat-site-emphasis.yaml`.

## The owner's words

> I'd like the site to be transparent about the current state including what we may eventually test with customers.
>
> I'd like to change the emphasis of the site, instead of putting the ontology as the front and center talking piece, instead, I'd like to focus more on what the ontology enables.
>
> I don't want to hide the ontology or not talk about it, in fact, I think most of the elements within the site should stay the same. However, if we consider progressive disclosure, I think I would like to go something like "current PoC outcomes -> potential future outcomes -> rules as code (the thing that enables these outcomes) -> the conceptual model the rules as code constructs (the ontology)".
>
> It should almost be like, the 'deeper' into the site you go, the more operationally focused the insights and information becomes. Sort of like an information triangle but across the entire UX.
>
> If the experience ever gets so deep that its talking about the different standards that the knowledge graph operates within (OWL, etc.) it should not assume that the user knows what these things mean. An executive and a data engineer should be able to finish with a similar level of understanding about how the system operates (to the extent that can be reasonably managed).
>
> You are to complete this rework in this and one other session. Please first plan your approach considering the goals and what can reasonably be achieved in 1.5 Opus context windows. I'll use "high" effort for the next session too.
